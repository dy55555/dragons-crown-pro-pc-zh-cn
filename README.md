# Dragon's Crown Pro PC · 简体中文界面语言包

给 [saulob/dragons-crown-pro-pc](https://github.com/saulob/dragons-crown-pro-pc) 的 TRG 启动器做简体中文汉化，
**覆盖启动器全部界面**。不改任何功能逻辑、不含游戏本体、不含上游 exe。
官方升级后重新双击一次 bat 就能继续用。

> 覆盖包括游戏内按 **F1 / F10** 呼出的选项与金手指菜单：这两处的内嵌字体
> 也已一并换成中文子集，菜单里的中文可以正常显示。

## 一键汉化

1. 安装 Python 3（Windows 安装时勾选 *Add Python to PATH*）。
2. 把本文件夹放到任意位置；**推荐直接放进游戏安装目录**（和 `dragons_crown_pro.exe` 同级）。
3. 双击 **`一键汉化.bat`**。
4. 正常启动 `dragons_crown_pro.exe`，启动器界面即为简体中文。
   游戏内 `F1` 选项菜单、`F10` 金手指菜单里的中文也已能正常显示。

如果脚本找不到 exe，任选一种：

| 方式 | 操作 |
| --- | --- |
| 拖放（最省事） | 把 `dragons_crown_pro.exe` 直接拖到 `一键汉化.bat` 图标上 |
| 命令行 | `python apply_zh_ui.py --exe "完整路径"` |

> 运行前请先关闭启动器 / 游戏，否则 exe 被占用会写入失败（脚本会明确提示）。

## 官方升级后继续用（重点）

| 情况 | 你要做的 |
| --- | --- |
| 官方更新覆盖了 exe | **重新双击 `一键汉化.bat`**，一次搞定 |
| 更新后多了新设置项 | 新词条先显示英文；往 `zh-UI.tsv` 补一行译文，再跑一次 bat |
| 想确认当前是不是汉化版 | 双击 `检查状态.bat` |
| 想回官方原版 | 双击 `还原官方版.bat` |

升级后还能用，靠的是这几点：

- **按英文原文匹配**，不按行号、不按文件偏移。上游增删词条、重排顺序都不会错位。
- 脚本自动识别「exe 已被官方换成新版」，更新原版备份后重新打补丁；重复运行完全幂等。
- 内置两道保险：动到 Windows 导入表名字就**整批作废并报错**；文字由代码拼装的条目
  会自动连同指令立即数一起改，改不了就保留英文，**绝不写出半个汉字**。

## 改翻译 / 补词条

`zh-UI.tsv` 每行两列，用 TAB 分隔：

```
英文原文<TAB>简体中文译文
```

第一列是匹配用的英文原文，**不要改**；只改第二列。规则：

- 转义：`\s` = 空格，`\n` = 换行，`\t` = 制表符，`\\` = 反斜杠。
- `%s` / `%d` 等占位符必须和英文原文**数量一致**。
- 以 `#` 开头的是注释行。
- 未收录的词条一律回退为英文，不会串出上游自带的葡语。

> **译文要尽量短。** 汉化是「就地替换」，中文占的字节数不能超过英文原文
> （一个汉字 3 字节，通常 10 个汉字 ≈ 30 字节）。超长的条目脚本会列出来，
> 改短后重跑即可。

改完重新双击 `一键汉化.bat` 生效。想贡献译文欢迎提 PR。

## 不影响哪些东西

只改 exe 里的**显示层**，不碰任何逻辑：

| 改动 | 作用 |
| --- | --- |
| `.rdata` 里的英文界面字面量（就地等长替换） | 启动器界面文字换成中文 |
| `.text` 三处内联字体名 + `.rdata` 三份字体名字符串 | Segoe UI → `simhei.ttf`，让启动器中文有字形 |
| ImGui 默认字形范围 `0x20–0xFF` → `0x20–0x9FFF` | 让中文字形被光栅化 |
| 内嵌 `DejaVuSans.ttf` → `zh-overlay.ttf`（就地替换 + 补零到原长） | 让 F1 选项 / F10 金手指菜单的中文有字形 |

**不改**：`user/dcp.ini`（游戏内语言、窗口、显卡、金手指开关一概不动）、存档、
联机 / 好友码、奖杯、金手指逻辑与数值、任何游戏文件（CPK / PKG / eboot）。

### 🔒 内部键保护（关键：绝不能把功能键也译成中文）

有少数英文串**长得像界面文字，实际是代码拿来比较的键**。一旦译成中文，比较就会
永远不成立，功能直接坏掉。脚本用整段上下文锚点识别并跳过它们：

| 受保护串 | 位置 / 用途 | 误改后果（已实际踩过） |
| --- | --- | --- |
| `Cheats` ×3 | 金手指签名表的 `spec.feature`、诊断分类键 | F1/F10 金手指全部失效：`cheat set sites: incomplete`，菜单变「不可用」 |
| `Direct connections` | 联机连接测试 `connection_test.cpp` 的判断键 | 联机诊断不显示直连问题的解决建议 |
| `Router configuration` | 同上 | 联机诊断不显示路由器配置的解决建议 |

v1.4.0 新增的角色编辑器又带出一组同类词：**六个职业名**
`Fighter` / `Amazon` / `Elf` / `Dwarf` / `Wizard` / `Sorceress`。
`ClassName()` 的返回值既显示在编辑器列表里，又被拼进外观缓存文件名和网络纹理路径
（`PLAYER/FIGHTER0…_NET.ftx`）以及 Boss 战文本键。译成中文会让这些路径/键对不上，
破坏外观同步。因此这六个词**不收进译文表**（保持英文显示），只在编辑器里以英文职业名出现。

> 这也是本项目的血泪教训：曾把 `Cheats` 全部 5 处一律译成「作弊」，其中 3 处是内部键，
> 结果金手指全废。现在同一词的 5 处里只有真正显示的 2 处会汉化，3 处内部键保持英文。
> 配置键（`windowed`/`borderless`/`0`/`1`/`16:9` 等内部值）同样逐处核对过，全部未动。

> 游戏内「菜单与字幕语言」请用启动器那个下拉框自己选，跟本语言包无关。

## 工作原理（简版）

上游启动器是 ImGui + 一层极薄的 C++ 外壳。它的界面文字有两类来源：

1. **`.rdata` 里的英文字面量** —— 侧边栏 `Ui::NavItem("Graphics")` 这类直接写字面量，
   不走 `Tr()` 翻译函数。本语言包就是把这些字面量**就地**换成中文（中文更短，补 NUL），
   所以不需要改任何引用地址、也不用改文件长度或 PE 结构。
2. **运行时由代码拼出来的串** —— 少数文字是「`.rdata` 前 N 字节 + 指令里的 8 字节立即数」
   拼成的，例如 `Check the game files and start` + `"playing."`（后者是 `movabs rcx, imm64`）。
   这类串只改 `.rdata` 会被立即数盖掉，出现「半个汉字 + aying.」。脚本会先扫描
   `movups xmm, [rip+…]` 确认哪些串被整块拷走，再找紧邻的 `movabs` 立即数，
   把中文按同样的切分点分开写进去。

   ★ 拼接点必须**按副本位置分别**记录：同一个词在 exe 里常有多份，通常只有一份是
   拼接的。曾把拼接切分点套到全部副本，导致 `Borderless Fullscreen` 四处全变成
   「无边框全+llscreen」的残串。现在每份副本各按自己的切分点处理，并在末尾统一
   清零残留字节。译文也尽量压到槽长以内，避免依赖立即数。
3. **定点补丁** —— 有少数词通用规则处理不了，用整段上下文做锚点单独修：

   | 词 | 问题 | 做法 |
   | --- | --- | --- |
   | `Play` | 紧贴显示器名尾部（`Generic PnP Moni`+`Play`），「前一个是 NUL 才算串首」的防误改规则会跳过它 | 锚点定位后定点写「玩」 |
   | `About` | 5 字符槽装不下 6 字节的「关于」，通用逻辑会走迁移分支，但导航块没有引用地址可改 | 借用紧邻的空闲 NUL 字节，就地写「关于」，不移动任何字节 |
   | `Russian` | 表里有小写 `russian`（内部语言键，绝不能动）和大写 `Russian`（显示名） | 只改显示名为「俄语」 |

字体是第二道坎。exe 里有**两套各自的 ImGui 上下文**，字体要分别处理，但文字来源其实是
同一批 `.rdata` 字面量（上游 `gpu/shim/dcp_overlay.cpp` 用 `dcp::Tr(...)` 取词，
`launcher/localization/ui_text.cpp` 也用同一个 `Tr()`）——所以文字早就汉化好了，
方块纯粹是「字体里没有对应字形」：

| 渲染 contexts | 谁在用 | 字体 | 处理 |
| --- | --- | --- | --- |
| 启动器 ImGui | 启动器主窗口、各设置页 | `Segoe UI` → 系统黑体 `simhei.ttf` | 改字体名 6 处 + 字形范围 |
| 游戏内 ImGui（overlay） | **F1 选项菜单 / F10 金手指菜单** | 内嵌 `DejaVuSans.ttf` → 中文子集 `zh-overlay.ttf` | 就地替换字体数据 |

启动器的字体名在 exe 里有两种形态，必须都改：`.text` 里三条 `movabs rax,"segoeui."` 内联立即数，
以及 `.rdata` 里三份独立字符串 `segoeui.ttf` / `seguisb.ttf` / `segoeuib.ttf`。

字体名换好还差一道：ImGui 默认只把 `0x20–0xFF` 烘焙进字形图集，中文不在范围内仍是菱形。
把范围数组高界从 `0xFF` 扩到 `0x9FFF`。这是个 **u16 小端数组** `{0x20, 0xFF, 0}`
（字节 `20 00 ff 00 00 00`），要整体写成 `{0x20, 0x9FFF, 0}`（字节 `20 00 ff 9f 00 00`）。
曾只改单个字节得到高界 `0x009F`，现在已修正，`--check` 能识别这种改错。

**F1 / F10 菜单是另一套独立字体。** 上游用汇编 `.incbin` 把 `DejaVuSans.ttf`（759676 字节）
原样嵌进 exe，`AddFontFromMemoryTTF` 加载；这个字体只有拉丁/西里尔字形，没有汉字。
本工具把随包的 `zh-overlay.ttf`（从**微软雅黑**按全部译文字符做的精简子集，435124 字节）
**就地写回原位置**，尾部补零到 759676 字节——不动任何指针和偏移。
三重校验（字体头签名 + 原长度 + 紧随其后的 `18.0f` 立即数）确保只改这一处、不会误伤。

字体收录：全部译文汉字 + ASCII + 三个关键符号：

| 符号 | 码点 | 用途 |
| --- | --- | --- |
| `‹` `›` | U+2039 / U+203A | F1 选项菜单里左右切换取值的箭头（`‹ Windowed ›`） |
| `·` | U+00B7 | 在线页 /「不兼容」提示的分隔点 |

> 一开始用的是 `simhei.ttf`，但它**没有** `‹ ›` 字形，菜单里那两个箭头会变成 `?`。
> 换用微软雅黑后解决 —— 需要重做字体时跑 `python build_overlay_font.py` 即可，
> 别改回 simhei。`--check` 会显示这套字体的当前状态。

## 存档编辑器（SAVE0.DAT）

附赠一个独立的存档编辑器，改装备/金币等，**已实机验证有效**。

### 用法

双击 `存档编辑器.bat`（需要带 tkinter 的官方 Python 3；bat 会自动挑一个）。
**编辑前先完全退出游戏。** 左侧树展开 DATA slot → 角色 → 行囊1–9：

* 角色不是「主装备/备用装备」两套，而是**最多 9 套行囊配置**（实测 9 套：行囊1/2 是主力配装，行囊3–9 多为备用短弓/披风）；
* 点「行囊N」这一层，右侧会列出该套 10 个格子，每格都有【编辑】按钮；
* 点具体 `[n]` 格子：装备可改物品ID、品质词条 1-8、装备等级、攻击力、耐久；消耗品可改种类和数量；
* 点角色节点可改等级/HP/技能点，并**只读**看到人物状态候选值和技能说明；
* 点 DATA 节点下的 **[通用道具箱]** 可改该存档 20 格共用道具箱的种类/数量（标 [技能] 的格子只读）。

点「保存改动」。保存时自动备份原档为 `SAVE0.DAT.editor-bak`，重算 CRC32 并校验通过才写盘。

命令行也能用：

```
python save_editor.py list                                   # 列出所有角色与装备
python save_editor.py set-item --slot 0 --char 0 --bag 0 --slot-idx 0 --id 0x105
python save_editor.py set-qty  --slot 0 --char 0 --bag 0 --slot-idx 5 --qty 20
python save_editor.py set-mod  --slot 0 --char 0 --bag 0 --slot-idx 0 --index 0 --id 0x103
python save_editor.py set-stat --slot 0 --char 0 --bag 0 --slot-idx 0 --field durcur --value 2000
python save_editor.py set-stat --slot 0 --char 0 --bag 0 --slot-idx 0 --field level --value 40
python save_editor.py set-gold --slot 0 --value 12345678
python save_editor.py set-box  --slot 0 --index 10 --qty 99            # 通用道具箱第11格数量
python save_editor.py set-box  --slot 0 --index 10 --kind 0x190        # 改种类为陨石卷轴
```

`--bag` 取 `0–8`，对应界面的「行囊1–9」。

### 已搞清的存档结构（CUSA10209 1.00 Asia/HK）

| 项 | 偏移 / 值 |
| --- | --- |
| 文件大小 | `0x20EB18`，固定 |
| 文件头 | `0x00` = u32 CRC32（覆盖 `[4, EOF)`，标准 IEEE 反射多项式 `0xEDB88320`）；`0x04` = `DCSD` |
| DATA slot | 3 个，stride `0xAF8D4` |
| 金币 | slot 基址 + `0xAF288`，u32 小端 |
| 角色记录 | slot 基址 + `0xA400` + 角色号 × `0x21D0`，共 16 个 |
| 角色字段 | HP `+0xDC/+0xE0`、技能点 `+0xF4`、等级 `+0xF6`(u8, 存值=显示−1)、职业 `+0xF7`、名字 `+0x208`(8字节) |
| **9 套行囊** | 角色基址 + `0x288` + 行囊号 × `0x354`（行囊号 `0–8`），每套 10 格 × `0x54` 字节；`0x354 = 10×0x54 + 0x14`。旧的「备用栏 `0x5DC`」其实就是第 2 套起点 |
| **通用道具箱** | slot 基址 + `0xAF2D4`（= 金币 `+0x4C`），20 格 × `0x54`，结构同行囊消耗品：种类 = 词条槽1，数量 = `+0x0C` 低字节。该 slot 内所有角色共用 |
| **物品ID** | 每格首 2 字节，u16 小端，范围 `0x00BB`–`0x01E8` |
| **消耗品** | 物品ID 固定 `0x0070`；`+0x0C` 的**低字节** = 数量（实测 x20/x8/x4/x7 全部吻合），词条槽 1 = 种类ID；数量 `0xFF` 表示不可堆叠的特殊物品 |
| **词条槽** | 在物品ID **往前 `0x40`** 处，8 个槽 × 8 字节：u16 词条ID + u16 flags + f32 参数；`0xFFFF` = 空槽 |
| **品质** | 由生效词条数决定：`E`=0、`D`=1、`C`=2、`B`=3、`A`=4、`S`=5（实测 A级猎人之弓 4 条、S级预言坠饰 5 条） |
| **装备等级** | 物品ID `+0x0E` u8，显示等级 = 存值 + 1（实测 `0x22` → LV35） |
| **攻击力/数值** | 物品ID `+0x10`/`+0x11` 两个 u8；武器是 ATK 上下限（弓 `0x56/0x60` → 86-96；长弓 `0x5C/0x5F` → 92-95） |
| **耐久** | 物品ID `+0x04`/`+0x08` u32，显示值 = 存值 ÷ 100（195889 → 1958） |

### 关于「备用装备」其实是 9 套行囊

角色并不是只有「主装备 / 备用装备」两套。实测每套起点是 `角色基址 + 0x288 + 行囊号×0x354`，
行囊号 `0–8` 共 9 套，每套 10 格。以精灵 Natalia 为例：行囊1 = 猎人长弓/预言坠饰/守护者之靴…，
行囊2 = 长弓/王室护身符/皮靴…，行囊3–9 = 备用短弓/皮制披风。
旧的「备用栏 `0x5DC`」正好是 `0x288 + 0x354`，也就是第 2 套；而更早的 `0x630` 是第 2 套的第 2 格，会漏掉第一件。

### 通用道具箱

每个 DATA slot 在金币之后 `+0x4C`（`slot基 + 0xAF2D4`）有连续 **20 格**道具箱，结构和行囊里的消耗品完全一样：
物品ID 固定 `0x0070`、种类 = 词条槽1、数量 = `+0x0C` 低字节。这 20 格是**该存档内所有角色共用**的，不属于某一个角色。
DATA1/2/3 各有自己独立的一套。

### 技能列表为什么只读

上游 `dcp_cheats.h` 里 `IsSkillItem()` 给出官方判定：消耗品的第一个词条（种类）ID 落在 `0x1D1–0x1F8`
且命中掩码 `0xE362E5F7FF`，就是「技能道具」。技能是装在行囊格子里、靠技能点上限制约的，
随意改写会造成技能点与装备不匹配，所以编辑器**只标注 `[技能]`、不开放修改**。

### 「洞察的 / 蛇眼的」这类前缀在哪

**结论：前缀不是独立字段，改不了、也没必要改。** 三条实测证据：

1. 「洞察的」= `Cerebral`、`蛇眼的` = `Serpent-eyed` 这类前缀ID（`0x412`、`0xAFC`…）在整个角色记录里 **0 命中**；
2. 物品头 `+0x0C` 对装备恒为 `0x0100`，也不是前缀；
3. 英文表里 `Pristine / Valkyrie's / Cerebral / Sage's / Branding` 这些「形容词」恰好是**词条ID**
   （预言坠饰的 5 个词条就是 `0x103/0xE7/0x11A/0x112/0x106`）。

也就是说，游戏是按装备身上的词条组合**动态生成显示名**（前缀 + 装备名）的。
你给的 xlsx 中文表把这些「形容词型」词条ID误标成了效果（如把 `0x103 Pristine` 写成「免疫中毒」），
所以中文名和游戏对不上——但改词条就改了属性，前缀显示会自动跟着变，不存在单独的「洞察的」地址。

### 人物状态字段

上游源码确认：人物属性（力量/体力/智力/幸运等）是由**职业 + 等级查表重算**的（`write_stats`），
`SAVE0.DAT` 里**没有独立的 STR/VIT/INT/LUC 字段**。角色记录 `+0xE4..+0xF2` 有 8 个随等级增长的 u16
（Lv65 精灵是 `[300,300,150,152,171,200,123,141]`），含义未最终标定，编辑器**只读展示、不开放修改**。
想调属性请改等级（游戏会按表重算）。

词条槽的位置以前读成「物品ID 往后 `0x14`」，那其实读到了**下一件装备**的词条——所以两件装备都被显示成 5 条。
正确位置是「物品ID 往前 `0x40`」，错开整整一格，实测弓 4 条、坠饰 5 条，与游戏一致。

物品ID对照表见 `save_items.tsv`（从你给的 xlsx 提取）；词条ID见 `save_affixes.tsv`。
xlsx 里的 `DEX`/`SW` 两列是同一16位ID的大小端两种读法，本工具按小端（`DEX`）解读，实机验证正确。

改装备时**只改物品ID这 2 字节 + 重算 CRC**，装备块里其余字节（耐久、词条、外观等）原样保留。
实测把「猎人之弓 `0x100`」改成「十字军之弓 `0x105`」、金币改成 `12345678` 后进游戏，
两者都生效。

> 换职业不匹配的武器（如战士拿法杖）游戏可能忽略或显示异常，建议换同类别物品。
> 词条中文名按「xlsx 中文表优先，其余照日式游戏惯用译法直译」处理（`build_mod_zh.py` 可重建），
> 先保证意思对；数值差得多的（例如表里 +30%、游戏里 +10%）以后逐条改 `save_mods.zh.tsv` 即可，
> 不用改程序。改 ID 本身是安全的。
> 存档格式针对 CUSA10209 1.00 亚洲/港版；其它构建未验证。改前备份，风险自负。
